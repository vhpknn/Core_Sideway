# AI READ SCOPE: ขอบเขตไฟล์ที่ AI อ่านได้ (แม่แบบ New_Strategies)

อัปเดต: 2026-11-20 | ถ้า AI เข้า GitHub ไม่ได้ ใช้ `python tools/make_ai_bundle.py --job <consult|build|coreupdate>`
ขัดกันเมื่อไรให้ยึดตามลำดับ: `docs/decisions/` > `docs/RULES.md` > ไฟล์นี้ > ไฟล์อื่น แล้วแจ้งผู้ใช้

## 1. หลักการ
- หนึ่ง Repo หนึ่งกลยุทธ์ AI เห็นเฉพาะ Repo นี้ ไม่อ้างโค้ดกลยุทธ์อื่นนอกจาก `reference/Hedge_example/` (ตัวอย่างรูปแบบ ไม่ใช่ให้คัดลอก Logic)
- Core ใน `Core/v*/` และ `Strategies/<ชื่อ>/v*/Core/` เป็นสำเนา อ่านได้ แก้ไม่ได้ (มติ D-06)
- ต้องการสิ่งนอกขอบเขต (เช่น Core ไม่มีความสามารถที่ต้องใช้): หยุด แจ้งผู้ใช้ และเปิดเป็นงาน Core ที่ Repo EA_Platform_Core
- เฟสงานดู `README_FIRST.md`: เฟส 1 ปรึกษา, เฟส 3 สร้างและทดสอบ, เฟส 4 อัปเดต Core

## 2. วิธีใช้ (ผู้ใช้)
เปิดแชตใหม่ วางข้อความเริ่มต้นจาก `docs/AI_START_PROMPT.md` ก่อนตอบสรุป AI ต้องแจ้งรายชื่อไฟล์ที่เปิดอ่านจริงทั้งหมด

## 3. กติกาสำหรับ AI
1. อ่านเฉพาะไฟล์ในรายการอนุญาตของเฟสที่ได้รับ และไฟล์ในหมวด "ทุกเฟส"
2. ห้ามเปิดไฟล์ในหมวด "ห้ามอ่าน" แม้เห็นลิงก์ชี้ไป ถ้าลิงก์ชี้มา ให้บอกผู้ใช้
3. ต้องการไฟล์นอกรายการ: ระบุ Path เต็ม เหตุผล และรอผู้ใช้อนุญาต (ครั้งละไม่เกิน 5 ไฟล์)
4. ชื่อฟังก์ชันหรือ API ต้องมาจากไฟล์โค้ดที่เปิดอ่านจริง ห้ามเดา ไม่มีให้บอกว่าไม่มี
5. ทุกกติกาที่อ้างต้องบอกชื่อไฟล์ที่มา สิ่งที่เป็นข้อเสนอของ AI ให้บอกว่าเป็นข้อเสนอ
6. Repo ที่อ่านได้คือสิ่งที่ผู้ใช้ Push แล้ว ถ้าผู้ใช้บอกว่าแก้ในเครื่อง ให้ขอเนื้อไฟล์จากผู้ใช้
7. AI ไม่แก้ไฟล์บน GitHub ไม่ Commit ไม่ติด tag ไม่สร้าง branch ผู้ใช้ทำเอง
8. ไฟล์ที่มีอยู่แล้วส่งแก้เป็น Jigsaw Patch (FIND/REPLACE) ตาม `docs/handoff/JIGSAW_PATCH_RULE.txt` ไฟล์ใหม่ส่ง Full Code พร้อม Path
9. ห้ามแก้สำเนา Core ใช้ `tools/update_core.py` เมื่อต้องการ Core ใหม่
10. เริ่มงานต่อจากแชตเก่า: อ่าน `docs/work/CURRENT_STATE.md` แล้วตรวจกับ Repo แจ้งผู้ใช้ถ้าไม่ตรง
11. ตั้ง TAG และ Magic ใหม่: เตือนผู้ใช้ให้ตรวจว่าไม่ซ้ำกับกลยุทธ์อื่นบนบัญชีเดียวกัน (ดู R-3 ใน `docs/RULES.md`)

## 9. ตรวจว่า AI ทำตามขอบเขต
