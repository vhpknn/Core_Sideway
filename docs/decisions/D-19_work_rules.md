# D-19: กติกาการทำงาน Commit และการทดสอบ (2026-10-26, ผู้ใช้สั่ง)

## D-19.1 Jigsaw Patch Rule (รวมข้อความจาก Handoff v4 ข้อ 4.2 และคำสั่งล่าสุด)
- แก้โค้ดเป็นชิ้นเล็กทีละชิ้น ไม่ส่ง Full Code ของไฟล์จนกว่าผู้ใช้พิมพ์ขอ เช่น "ขอ fullcode <ชื่อไฟล์>"
- ผู้ช่วยไม่แก้ไฟล์บน GitHub เอง ผู้ใช้เป็นผู้นำโค้ดเข้าไฟล์และ Commit เอง
- Commit เมื่อจบ PHASE ใหญ่เท่านั้น (เช่น PHASE 1.1 ถึง 1.10 ไม่ Commit; Commit เมื่อเริ่ม PHASE 2)
- ข้อความเต็มต้นฉบับของ Jigsaw Patch Rule ผู้ใช้ยังไม่ได้ส่ง ฉบับนี้เป็นการสรุปจากที่ผู้ใช้ระบุ

## D-19.2 กติกาการทดสอบ
- ทดสอบหลังสร้าง/แก้เสร็จเท่านั้น ไม่ทดสอบระหว่างทาง ทดสอบให้ครบทุกจุดแล้วสรุปจุดที่ไม่ผ่านทั้งชุด
- แก้เฉพาะจุดที่ไม่ผ่าน แล้วทดสอบซ้ำเฉพาะจุดนั้น ไม่เริ่มใหม่ทั้งหมด
- ข้อควรประกอบ (ข้อเสนอผู้ช่วย รอผู้ใช้ยืนยัน): (ก) คอมไพล์ 0 errors เป็นเกณฑ์ผ่านของแต่ละ PHASE ย่อย ไม่ถือเป็นการทดสอบการทำงาน (ข) ทำ Test Matrix ก่อนเริ่มทดสอบ (รหัสข้อทดสอบ ผลที่คาดหวัง หลักฐาน ผล) (ค) ถ้าการแก้กระทบฟังก์ชันที่ถูกเรียกจากจุดอื่น ให้ทดสอบซ้ำจุดที่เรียกฟังก์ชันนั้นตามระดับใน Blueprint v4 ข้อ 5.2

## D-19.3 ลำดับโปรเจกต์
- ทำทีละโปรเจกต์ เริ่มจาก Core หลัก เมื่อทดสอบผ่านทุกจุด 100% แล้วจึงสร้างกลยุทธ์เพิ่ม
- กลยุทธ์แรกหลัง Core คือ Pending Order (EA ลำดับ 2, TAG PND)
- ข้อเสนอผู้ช่วย (รอผู้ใช้ยืนยัน): Core v1.0 มีเฉพาะสิ่งที่ Hedge ใช้และทดสอบได้ ฟังก์ชันออเดอร์ค้างและการนับออเดอร์ค้างใน Basket API เพิ่มใน Core v1.1 พร้อมโปรเจกต์ Pending และทดสอบเฉพาะส่วนที่เพิ่ม เพื่อให้คำว่า "Core ผ่าน 100%" เป็นจริงตามหลักฐาน
