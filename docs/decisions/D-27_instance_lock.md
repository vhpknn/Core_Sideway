# D-27: ป้องกันแนบ EA ซ้ำ Magic เดียวกัน (2 พ.ย. 2026 ผู้ใช้สั่ง)

ยกเลิกมติเดิมใน `PHASE1_DECISIONS.md` ตาราง "ผู้ช่วยตัดสินแทน" แถว "ล็อกอินสแตนซ์ | ไม่ทำ ใช้ Magic ไม่ซ้ำ + Identity Check + ทะเบียน | YAGNI"

## เหตุผล
- ข้อ A-05 (Magic 10005) มี EA 2 ตัวรันพร้อมกัน (กราฟ H1 และ M30) บนบัญชี Symbol และ Magic เดียวกัน ผลคือทุกคำสั่งซ้ำสองชุด (เช่น `[BREAK-EVEN]` สองบรรทัดเวลาเดียวกัน) และคำสั่งปิดของตัวที่สองล้มเหลว `retcode=10039 (Order to close this position already exists)` หรือ `retcode=10036 (Position doesn't exist)`
- `Core_Identity` ตรวจเฉพาะรูปแบบ TAG/Magic/Comment ไม่ตรวจว่ามี EA อื่นใช้ Magic นี้อยู่ ทะเบียน Magic ช่วยไม่ได้เมื่อผู้ใช้แนบ EA ตัวเดิมซ้ำ
- ตอนเทรดจริง สองตัวแย่งจัดการไม้เดียวกันเป็นความเสี่ยงสูง

## มติ
- ทำใน Core v1.0.1 (ไม่แก้ v1.0.0)
- ขอบเขต: ตรวจต่อชุด (บัญชี, Symbol, Magic)
- พฤติกรรมเมื่อพบซ้ำ (ข้อเสนอเริ่มต้น ยืนยันในขั้นปรึกษาของ v1.0.1): หยุดตัวที่แนบทีหลัง (`INIT_FAILED` พร้อม Alert บอก Magic และกราฟที่ล็อกอยู่) ตัวแรกทำงานต่อโดยไม่กระทบ

## กลไกที่เสนอเดิม (ถูกแทนที่ด้วยหัวข้อ "มติรายละเอียด 4 พ.ย. 2026" ท้ายไฟล์)
- ตัวแปรถาวร `<TAG>S_<บัญชี>_<Symbol>_<Magic>_LOCK` เก็บ ChartID ของกราฟเจ้าของล็อกและเวลา heartbeat
- ตัวที่สองเห็น heartbeat ยังสดของกราฟอื่น = ปฏิเสธ ถ้า heartbeat หมดอายุ (EA เดิมค้าง/MT5 ดับ) = ยึดล็อกได้
- เปลี่ยน Timeframe หรือกด F7 แก้ Input บนกราฟเดิม ต้องไม่ถูกบล็อกตัวเอง (ChartID เดิม)
- Strategy Tester ต้องไม่ถูกบล็อกและไม่เขียนตัวแปรถาวรจริง (สอดคล้องข้อ B-08)
- เพิ่มคีย์ `LOCK` ในการตรวจความยาวคีย์ไม่เกิน 63 ของ `CoreStateInit`
- ถ้ามี input ใหม่ ต้องมีป้ายไทยและอังกฤษตาม D-26.1

## มติรายละเอียด 4 พ.ย. 2026 (ผู้ใช้เลือกตามข้อเสนอผู้ช่วย)
- กลไก: ตัวแปรกลางชั่วคราว (GlobalVariableTemp) ชื่อ `<TAG>S_<บัญชี>_<Symbol>_<Magic>_LOCK` ค่า 0 = ว่าง ค่าอื่น = รหัสเจ้าของ จองด้วย GlobalVariableSetOnCondition (เช็คและเขียนแบบแบ่งแยกไม่ได้) ตัวแปรชั่วคราวหายเองเมื่อปิด MT5
- ไม่ใช้ heartbeat และตัวจับเวลา ไม่แก้ไฟล์ EA ของกลยุทธ์ (include โมดูลล็อกจาก Core_Runtime.mqh)
- รหัสเจ้าของต้องมาจาก ChartID โดยไม่เสียความแม่นยำ (ChartID เป็นเลข 64 บิต ตัวแปรกลางเก็บ double 53 บิต) วิธีเข้ารหัสยังไม่ตัดสิน ต้องผ่านข้อทดสอบ I-10 ก่อน
- จองตอน CoreOnInit หลัง CoreStateInit ก่อน EngineInit ปล่อยล็อกทุกครั้งที่ OnDeinit และเมื่อ init ล้มเหลวหลังจองแล้ว กราฟเจ้าของเดิมจองคืนได้
- ตัวที่สองที่พบล็อกของกราฟอื่น: คืน INIT_FAILED พร้อม Alert บอก Magic และกราฟเจ้าของ ตัวแรกทำงานต่อไม่กระทบ
- Strategy Tester: ข้ามการล็อก ไม่เขียนตัวแปรจริง
- เพิ่มคีย์ LOCK ในการตรวจความยาวไม่เกิน 63 ของ CoreStateInit
- มติเลขรุ่นโฟลเดอร์และขอบเขต v1.0.1 อยู่ที่ D-28

## ผลทดสอบก่อนออกแบบ 6 พ.ย. 2026 (สคริปต์ Test_InstanceLock ชุด 1A)
- ChartID บนเครื่องผู้ใช้เป็นเลข 14 หลัก ไม่เสียความแม่นยำใน double แต่คงการตัดเหลือ 52 บิต (2^52-1) ไว้เพื่อกันเครื่อง/Build อื่น และใช้ 1 แทน 0 เมื่อผลเป็น 0
- GlobalVariableTemp เรียกซ้ำเมื่อมีอยู่แล้วคืน false error 4502 โค้ดถือเป็นปกติ
- GlobalVariableSetOnCondition ล้มเพราะเงื่อนไขไม่ตรง = error 4503, ตัวแปรไม่มี = 4501
- ปล่อยล็อกเฉพาะเจ้าของด้วย SetOnCondition(ชื่อ, 0, รหัสเรา) และเก็บชื่อคีย์ที่จองจริงไว้ปล่อย (กันกรณี Symbol/Magic เปลี่ยน)
- ไฟล์ที่เกี่ยวข้อง: Core/v1.0.1/include/Core_Lock.mqh (ใหม่), Core_Runtime.mqh, Core_Utils.mqh (คีย์ LOCK)
