# D-28: เลขรุ่นโฟลเดอร์กลยุทธ์ตรงกับ Core และขอบเขต Core v1.0.1 (4 พ.ย. 2026 ผู้ใช้สั่ง)

## D-28.1 เลขรุ่นโฟลเดอร์
- โฟลเดอร์กลยุทธ์ `Strategies/<ชื่อ>/v<X>/` ใช้ Core รุ่น `Core/v<X>/` เลขเดียวกันเสมอ
- ตัวอย่างการจับคู่ที่ตัดสินแล้ว:

| Core | กลยุทธ์ | หมายเหตุ |
|---|---|---|
| Core/v1.0.0 | Strategies/Hedge/v1.0.0 | ฐานปัจจุบัน แช่แข็ง |
| Core/v1.0.1 | Strategies/Hedge/v1.0.1 | สำเนา Hedge สำหรับทดสอบ Core v1.0.1 พฤติกรรม Hedge ต้องไม่เปลี่ยน |
| Core/v1.1 | Strategies/Pending/v1.1 | Core รุ่นที่เพิ่มออเดอร์ค้าง |

- ลำดับงานที่ตัดสินแล้ว: Core v1.0.1 แล้ว Core v1.1 แล้ว Pending/v1.1 แยกเป็นก้อนเล็ก ไม่รวมเป็นก้อนเดียว (ตาม `docs/handoff/HANDOFF_CORE_V1_1.md`)
- สร้าง Core รุ่นใหม่ด้วยการคัดลอกโฟลเดอร์รุ่นก่อนเป็นโฟลเดอร์ใหม่ แล้วแก้เฉพาะรุ่นใหม่ รุ่นเก่าและกลยุทธ์รุ่นเก่าไม่ถูกแก้ (แช่แข็ง)
- กลยุทธ์ที่ไม่ย้ายรุ่น ยังอยู่โฟลเดอร์รุ่นเดิมได้
- Magic และทะเบียน Magic ไม่ผูกกับเลขรุ่นโฟลเดอร์

### ผลต่อเครื่องมือ (ต้องทำและทดสอบแยกก่อนสร้าง `Core/v1.0.1`)
- `sync_core`: จับคู่ `Strategies/<ชื่อ>/v<X>` กับ `Core/v<X>` เอง เมื่อมี Core มากกว่าหนึ่งรุ่นห้ามรันแบบคัดลอกทับทุกสำเนาโดยไม่ระบุเป้าหมาย
- `verify_core`: เทียบแต่ละสำเนากับต้นฉบับรุ่นเดียวกัน และตรวจว่า `core_version` ใน `CORE_MANIFEST.txt` ตรงกับเลขรุ่นของโฟลเดอร์กลยุทธ์
- ห้ามคอมไพล์ก่อน sync ตามลำดับ D-26.4 เหมือนเดิม

### เรื่องที่ยังไม่ตัดสิน
- เลขรุ่นของกลยุทธ์ที่แก้โดย Core ไม่เปลี่ยน (เช่น แก้บั๊กเฉพาะ Hedge) ยังไม่มีเลขรุ่นรองรับ (กรณี InpMaxAutoRounds ตัดสินใน D-31.5: แก้ในโฟลเดอร์เดิม ติด tag แยก ส่วนกติกาทั่วไปยังไม่ตัดสิน)

## D-28.2 ขอบเขต Core v1.0.1
- ทำ: BACKLOG ข้อ 1 (ป้องกันแนบ EA ซ้ำ ตาม D-27) และข้อ 2 (ลบบล็อก `#ifdef PANEL_LEGACY_BUILD` ใน `Core_Panel.mqh`) และข้อ 3 ที่ไม่อยู่ใน BACKLOG เดิม: เพิ่ม Input `InpIdentityCheck` เปิด/ปิดการตรวจ Identity (D-12) ค่าเริ่มต้นปิด เมื่อปิดไม่มี Alert ไม่มีแถวแดงที่ Panel และไม่มี Log (ผู้ใช้สั่ง 4 พ.ย. 2026)
- ข้อยกเว้นสำหรับการทดลอง: ผู้ใช้ใช้ Magic อิสระและ Comment เป็นป้ายอธิบายชุดค่า ไม่ต้องลงทะเบียนใน MAGIC_REGISTRY และเก็บไฟล์ชุดค่าทดลองนอกโฟลเดอร์ Set ของ Repo (verify_core ตรวจ Comment และช่วง Magic ของไฟล์ในโฟลเดอร์ Set)
- ไม่ทำใน v1.0.1: F-01 และ F-02 (BACKLOG ข้อ 4) ย้ายไปรุ่นแก้ไขหลัง Core v1.1 ข้อความใน D-22 ที่ว่า "แพตช์ใน v1.0.1" ให้อ่านตามข้อนี้
- ขยายขอบเขตตาม D-30 (18 พ.ย. 2026 ผู้ใช้สั่ง): เพิ่ม Input `InpSession1Close` ถึง `InpSession3Close` และ `InpCountExternalClose` ใน Core v1.0.1 รายละเอียดและข้อจำกัดอยู่ใน D-30
- ทดสอบ v1.0.1: ทำ Test Matrix ก่อน แล้วทดสอบเฉพาะส่วนที่เพิ่ม ผู้เรียกทั้งหมด และ Hedge smoke ตามผลกระทบ (ตาม `docs/handoff/HANDOFF_CORE_V1_1.md`)
