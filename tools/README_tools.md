# README tools: เครื่องมือของแม่แบบ New_Strategies

ทุกตัวเป็นไฟล์ `.bat` (ดับเบิลคลิกได้) ที่เรียกสคริปต์ Python 3 ในโฟลเดอร์เดียวกัน ต้องติดตั้ง Python 3 (เลือก "Add to PATH") ใช้ไลบรารีมาตรฐานเท่านั้น
ไม่มีทะเบียน Magic กลางและไม่มี `next_magic`: TAG ลำดับ และ Magic ฐานกำหนดตอนรัน `init_strategy` (ดู R-3 ใน `docs/RULES.md`)

## 1. ใช้ตัวไหนตอนไหน
| เครื่องมือ | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| `init_strategy` | ตั้งชื่อกลยุทธ์จากแม่แบบ: เปลี่ยน Strategies/Template เป็นชื่อใหม่ ตั้ง TAG ลำดับ Magic ฐาน | ครั้งเดียว หลังปรึกษาจนสรุปสเปกแล้ว (เฟส 2) |
| `update_core` | นำ Core รุ่นใหม่จาก EA_Platform_Core เข้ามาเป็นโฟลเดอร์รุ่นใหม่ข้างของเดิม พร้อมรายการตรวจ | เมื่อ Core หลักออกรุ่นใหม่ (เฟส 4) |
| `sync_core` | เทียบ/คัดลอก Core ต้นฉบับ (Core/v*/include) ไปทับสำเนาใต้กลยุทธ์ | เมื่อสำเนา Core ไม่ตรงต้นฉบับ (ไม่ใช้กับ Core รุ่นใหม่ ให้ใช้ update_core) |
| `verify_core` | ตรวจสำเนา Core, ธีม, ค่าตัวตนใน EA และไฟล์ .set | ก่อน Commit ทุกครั้ง |
| `check_docs` | ตรวจเอกสาร: ไฟล์หลักครบ, เลขมติ, path ที่อ้าง, ขอบเขต AI | ก่อน Commit ทุกครั้ง |
| `run_checks` | รัน sync_core (ดูอย่างเดียว) + verify_core + check_docs แล้วรวมผลเป็นไฟล์เดียว | ทุกครั้งก่อน Commit และก่อนส่งผลให้ AI |
| `make_ai_bundle` | รวมเอกสารและโค้ดเป็นชุดไฟล์สำหรับ AI ที่เข้า GitHub ไม่ได้ | เริ่มแชตกับ AI ในแต่ละเฟส |
| `log_entry` | ช่วยเขียนรายการใน `docs/work/LOG.md` (ต่อท้ายอย่างเดียว) | ทุกครั้งที่จบชุดงาน |
| `make_rangebot_sets` | สร้างไฟล์ `.set` ชุด Ablation 00 ถึง 10 ของ RangeBot ครบทุก Input (ค่าอยู่ในสคริปต์) ไม่ใส่ `--apply` = ดูแผนอย่างเดียว | เมื่อแก้ชุดค่าของ RangeBot (แล้วรัน `verify_core`) |

## 2. ลำดับประจำวัน
- **ก่อน Commit:** บันทึกไฟล์ > คอมไพล์ EA 3 ตัว (0 errors 0 warnings) > `run_checks.bat` > ดูว่า verify_core ERROR 0 และ check_docs ERROR 0 > `log_entry` > Commit
- **เริ่มกลยุทธ์ใหม่:** unzip แม่แบบ > ปรึกษา AI (เฟส 1) > `init_strategy` > คอมไพล์ > เปลี่ยนชื่อโฟลเดอร์เป็น `EA_<ชื่อ>` > `git init` > สร้าง Repo Private > push
- **Core หลักเปลี่ยนรุ่น:** `update_core` > คอมไพล์ > `run_checks` > ทดสอบ > Commit > ติด tag (ดู `docs/work/CORE_UPDATE_*.md` ที่เครื่องมือสร้างให้)

## 3. init_strategy
ตั้งชื่อกลยุทธ์จากแม่แบบ ต้องรันในสำเนาแม่แบบที่ยังไม่ตั้งชื่อ (ไม่มี `STRATEGY_IDENTITY.txt`) ไม่ใช่ใน Repo ของแม่แบบ เพราะเครื่องมือลบ `Strategies/Template` ทิ้ง
- รันแบบถามตอบ: `tools\init_strategy.bat` (ใส่ชื่อ, TAG 3 ตัวอักษร A ถึง Z, ลำดับ EA 1 ถึง 99) แสดงแผนแล้วถาม Y/N
- รันแบบระบุค่า: `python tools\init_strategy.py --name SMC --tag SMC --ordinal 3` (ใส่ `--apply` เพื่อเขียนทันที)
- Magic ฐาน = ลำดับ x 10000 และ Magic ทุกชุดค่าอยู่ในช่วงฐาน ถึง ฐาน+9999 Comment รูปแบบ `<TAG><ฐาน> H1 base`
- สแกนโฟลเดอร์ข้างเคียงของ Repo (`--scan <โฟลเดอร์>` เลือกเอง) และเตือนถ้า TAG ลำดับ หรือ Magic ฐานซ้ำกับกลยุทธ์อื่น (รวม HDG, PND, TDK ของแพลตฟอร์ม) ถ้าซ้ำจะไม่เขียนไฟล์ ยกเว้นใส่ `--ignore-collision`
- ผลลัพธ์: `Strategies/<ชื่อ>/` พร้อมชื่อไฟล์และค่าใหม่ (ไม่แตะไฟล์ใน Core), `STRATEGY_IDENTITY.txt`, และเติมค่าตัวยึดตำแหน่งแบบสองปีกกาของชื่อ TAG ลำดับ Magic ฐาน และวันที่ ในไฟล์ .md
- ไม่เปลี่ยนชื่อโฟลเดอร์ Repo ไม่ `git init` ไม่ Commit ทำเองตามขั้นต่อไปที่เครื่องมือพิมพ์บอก

## 4. update_core
นำ Core รุ่นใหม่เข้ากลยุทธ์โดยไม่แตะรุ่นเดิม (D-28.1: โฟลเดอร์กลยุทธ์ใช้ Core รุ่นเดียวกับชื่อโฟลเดอร์)
- ต้องมี clone ของ EA_Platform_Core ที่ checkout ตาม tag ของ Core รุ่นที่ต้องการ
- รัน: `tools\update_core.bat --platform <โฟลเดอร์ EA_Platform_Core> --version v1.0.2` แสดงแผนแล้วถาม Y/N (ใส่ `--apply` เพื่อเขียนทันที)
- ตัวเลือก: `--strategy <ชื่อ>` (ถ้ามีหลายโฟลเดอร์) | `--from-version v1.1` (ไม่ระบุ = รุ่นล่าสุดที่มี)
- ตรวจ platform (tag, commit, มีไฟล์ค้างหรือไม่) แล้วเทียบ Core เดิมกับใหม่ เพิ่ม ลบ แก้ และเทียบ `Core_StrategyAPI.mqh` พร้อมประเมินความเสี่ยงจากไฟล์ที่เปลี่ยน (เป็นการประมาณ ไม่ใช่การพิสูจน์): สูง = API เปลี่ยนหรือไฟล์ถูกลบ, ปานกลาง = มีไฟล์หรือ Input เพิ่ม, ต่ำ = แก้ภายใน
- สร้าง `Core/<รุ่นใหม่>/` (include + PINNED_FROM.txt), `Strategies/<ชื่อ>/<รุ่นใหม่>/` (คัดลอกจากรุ่นเดิม แล้วเปลี่ยน Core และเขียน CORE_MANIFEST.txt), และ `docs/work/CORE_UPDATE_<เดิม>_to_<ใหม่>.md` (รายการตรวจให้ติ๊กทีละข้อ)
- ถ้า platform ไม่ตรง tag หรือมีไฟล์ค้าง เครื่องมือเตือนแต่ไม่หยุด ไม่เขียนทับโฟลเดอร์ที่มีอยู่แล้ว
- ไม่แตะรุ่นเดิม ไม่ Commit ไม่ติด tag

## 5. sync_core
คัดลอก Core ต้นฉบับไปทับสำเนาของกลยุทธ์ ตรวจก่อน สำรองไฟล์เดิม ถามยืนยัน **ห้ามแก้ไฟล์ในสำเนาเอง** แก้ที่ต้นฉบับเท่านั้น (ซึ่งในแม่แบบนี้คือสำเนาที่ปักไว้ ให้ใช้ update_core)
- รันตรงๆ = ตรวจอย่างเดียว | `--apply` = คัดลอกจริงและถามยืนยัน | `--yes` ข้ามคำถาม | `--src` และ `--target` เลือกเอง
- สถานะ: `SAME` ตรงกัน, `DIFF` ต่างกัน, `MISSING` สำเนายังไม่มีไฟล์, `EXTRA` สำเนามีไฟล์เกิน (เตือนอย่างเดียว ไม่ลบให้)
- เมื่อมี Core มากกว่าหนึ่งรุ่น `--apply` ต้องระบุ `--target` เสมอ (D-28.1)
- ทุกครั้งที่คัดลอกจะสำรองไฟล์เดิมที่ `Strategies/<ชื่อ>/v*/Core/Core_backup/<เวลา>/` และเขียน `CORE_MANIFEST.txt`
- รหัสออก: 0 ตรงกันหมด, 1 พบความต่าง, 2 ผิดพลาด

## 6. verify_core
ตรวจ 3 เรื่องในครั้งเดียว ไม่แก้ไฟล์ใดๆ
1. สำเนา Core ตรงกับต้นฉบับรุ่นเดียวกัน และตรงกับ `CORE_MANIFEST.txt` (รวม `core_version` ตรงกับรุ่นของโฟลเดอร์)
2. ค่าทุกตัวใน `CoreUI_Theme.mqh` เท่ากับธีมต้นฉบับที่ `docs/reference/HedgeUI_Theme.mqh`
3. กลยุทธ์: `STRATEGY_TAG`, ลำดับ, Magic ฐาน (ต้องเท่ากับลำดับ x 10000) ใน `<ชื่อ>_EA.mq5`, ตรงกับ `STRATEGY_IDENTITY.txt`, และไฟล์ `.set` (Comment ขึ้นต้น `<TAG><Magic>` ไม่เกิน 25 ตัวอักษร, Magic อยู่ในช่วงฐาน ถึง ฐาน+9999, ไม่ซ้ำ)
| ข้อความ | แปลว่า | ต้องทำ |
|---|---|---|
| `DIFF` หรือ `MISSING` ที่สำเนา | สำเนาไม่ตรงต้นฉบับ | `sync_core` (ซ่อมสำเนา) หรือ `update_core` (รุ่นใหม่) |
| `ถูกแก้หลัง sync (ไม่ตรง manifest)` | มีคนแก้ไฟล์ในสำเนา | คืนไฟล์ด้วย sync_core ห้ามแก้ในสำเนา |
| `STRATEGY_IDENTITY.txt ไม่ตรงกับ #define ใน EA` | แก้ TAG หรือ Magic ฐานด้วยมือ | ทำให้ตรงกันทั้งสองที่ |
| `Comment ... TAG_MISMATCH / MAGIC_MISMATCH / COMMENT_TOO_LONG` | Comment ใน .set ผิดกติกา | แก้ `InpTradeComment` ใน .set |
| `Magic xxxxx ซ้ำ` | Magic ซ้ำในไฟล์ .set | เปลี่ยนเลข |
| `STRATEGY_MAGIC_NEXT ล้าสมัย` | เลขถัดไปใน EA เก่ากว่าที่ใช้ใน .set | แก้ `#define STRATEGY_MAGIC_NEXT` แล้วคอมไพล์ |
| `ไม่มีไฟล์ .set` | ยังไม่มีชุดค่า | ปกติสำหรับแม่แบบ ตั้งชุดค่าเมื่อเริ่มทดสอบ |
รหัสออก: 0 ไม่มี ERROR, 1 มี ERROR, 2 เครื่องมือผิดพลาด

## 7. check_docs
อ่านอย่างเดียว ตรวจ: ไฟล์เอกสารหลักครบ, มี `Core/v*/PINNED_FROM.txt`, เลขมติ `D-NN` (ของแพลตฟอร์ม) ต้องไม่เกินที่คัดลอกมา, เลขมติกลยุทธ์ `S-NN` ไม่ซ้ำและห้ามใช้ `D-NN`, `STRATEGY_IDENTITY.txt` ตรงกับโฟลเดอร์ และไม่มี `{{...}}` ค้างหลังตั้งชื่อ, path ในเอกสารหลักชี้ไปไฟล์ที่มีจริง, `docs/AI_READ_SCOPE.md` ไม่ขัดกันเองและไม่ขัดกับรายการไฟล์ของ `make_ai_bundle`, `docs/work/CURRENT_STATE.md` ไม่ตามหลัง HEAD เกิน 3 Commit
รหัสออก: 0 ไม่มี ERROR, 1 มี ERROR

## 8. run_checks
รัน `sync_core` (ตอบ N เสมอ ไม่คัดลอกอะไร), `verify_core`, `check_docs` แล้วรวมผลเป็น `tools/out/RUN_REPORT.txt` พร้อมสถานะ git เปิดไฟล์นี้ คัดลอกทั้งหมดไปวางให้ AI
- คอมไพล์ผ่านเครื่องมือ (ไม่บังคับ): `python tools\run_checks.py --compile Strategies/<ชื่อ>/v1.1/<ชื่อ>_EA_TH.mq5 --metaeditor "W:/.../MetaEditor64.exe" --portable`
- ไม่ระบุ `--metaeditor` = ให้กด F7 ใน MetaEditor เอง
- ผลที่ต้องได้ก่อน Commit: sync_core ตรงกันหมด, verify_core ERROR 0, check_docs ERROR 0 (WARN ยอมรับได้ถ้ารู้เหตุผล)

## 9. make_ai_bundle
รวมไฟล์สำหรับ AI ที่เข้า GitHub ไม่ได้ เขียนผลที่ `ai_bundle/<งาน>_<วันที่เวลา>/` เท่านั้น (ไม่แก้ไฟล์ใน Repo) รัน `check_docs` ก่อน ถ้ามี ERROR จะหยุด (ข้ามด้วย `--force`)
- `python tools\make_ai_bundle.py --job consult` เฟส 1 ปรึกษา (เอกสารกลาง, ฟอร์มสเปก, Core API ที่ปักไว้, Hedge ตัวอย่าง)
- `--job build` เฟส 3 สร้างและทดสอบ (โค้ดกลยุทธ์ รวม Core API ในสำเนา)
- `--job coreupdate` เฟส 4 อัปเดต Core (CORE_UPDATE ล่าสุด, Core_StrategyAPI ทุกรุ่น, โค้ดกลยุทธ์)
- ตัวเลือก: `--version v1.1` | `--add <path>` เพิ่มไฟล์ | `--redact <ข้อความ>` แทนด้วย [REDACTED] (เช่น เลขบัญชี) | `--out`
- ส่งให้ AI: `00_START_PROMPT.txt` (วางเป็นข้อความ) + `01_DOCS_BUNDLE.md` + `02_CODE_BUNDLE.txt` เปิดตรวจ `MANIFEST.txt` ว่าไม่มีไฟล์ขาด ถ้า Chatbot รับไม่ไหว ให้ตัดไฟล์ใหญ่ออกหรือแยกส่งเป็นรอบ
ค่าเริ่มต้น lite ตัดไฟล์ใหญ่ออกเพื่อประหยัด Token ใช้ --full เมื่อต้องการไฟล์ครบ

## 10. log_entry
เขียนรายการใหม่ใน `docs/work/LOG.md` (ต่อท้ายอย่างเดียว ไม่แก้รายการเก่า ไม่ Commit)
- `python tools\log_entry.py` สร้างร่างที่ `tools/out/LOG_DRAFT.txt` (เติมเวลา เลขรายการถัดไป รายชื่อไฟล์จาก git สรุปผล run_checks และสถานะ Commit ให้)
- แก้ช่อง `[[กรอก]]` เป็นข้อความจริง และตรวจช่อง `[[ตรวจ]]` แล้วลบเครื่องหมายออก
- `python tools\log_entry.py --append` ต่อท้ายเมื่อกรอกครบ (ตรวจรูปแบบก่อน) | `--tail 10` แสดง 10 รายการล่าสุด ไว้วางให้ AI | `--log <path>` ระบุไฟล์ LOG เอง

## 11. เครื่องมือเหล่านี้ไม่ทำ
- ไม่คอมไพล์ EA (ต้องกด F7 เอง ยกเว้นใส่ `--metaeditor` ให้ run_checks)
- ไม่ทดสอบการเทรดหรือพิสูจน์ว่าโค้ดถูกต้อง (ตรวจเฉพาะความสอดคล้องของไฟล์และกติกา)
- ไม่ Commit ไม่ push ไม่ติด tag ไม่เปลี่ยนชื่อโฟลเดอร์ Repo
- ไม่ลบไฟล์ใดโดยไม่แจ้ง (ยกเว้น init_strategy ที่ลบ Strategies/Template หลังสร้างชื่อใหม่ และ update_core ลบโฟลเดอร์ชั่วคราวของตัวเองเมื่อล้มเหลว)
